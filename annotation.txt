АННОТАЦИЯ

В этой сессии пользователя обучали базовым концепциям Kubernetes на практике, начиная от простого и постепенно переходя к более сложному. В качестве учебного проекта был создан небольшой web-сервис на FastAPI, упакованный в Docker и развёрнутый в локальном кластере Kubernetes (Kubernetes внутри Docker Desktop на macOS).

Пользователь:
- создал структуру проекта (app/ + k8s/),
- написал минимальное FastAPI-приложение (main.py),
- подготовил Dockerfile с uvicorn как ASGI-сервером,
- собрал и протестировал Docker-образ локально,
- включил встроенный Kubernetes в Docker Desktop и устранил проблемы подключения (EOF),
- описал Deployment для 3 реплик приложения,
- описал Service (ClusterIP), который по label’ам находит поды и прокидывает на них трафик,
- отладил типичную проблему ImagePullBackOff, поняв связь image, imagePullPolicy и локальных образов,
- использовал kubectl port-forward для доступа к приложению через Service,
- установил nginx Ingress Controller,
- описал и применил Ingress-ресурс, настроив маршрут host/path → Service,
- проверил конечный доступ к приложению через http://kubernetes.docker.internal/ и убедился, что ответ идёт из pod’ов Kubernetes (по полю hostname).

Особый акцент делался на:
- чётком разделении ролей Deployment, Service и Ingress;
- понимании label/selector как основного механизма связи объектов;
- работе с портами (containerPort, targetPort, port);
- типичных ошибках (ImagePullBackOff) и их причинах;
- пошаговой связи Docker → Kubernetes (образ → pod → Service → Ingress).


КРАТКИЙ УЧЕБНЫЙ ПЛАН ДЛЯ ПРОДОЛЖЕНИЯ

Уровень: уверенный разработчик с опытом Python/ML, начальный/средний уровень в DevOps и Kubernetes.

1. БАЗОВОЕ УКРЕПЛЕНИЕ (повторение и закрепление)
   - Повторить: понятия Cluster, Node, Pod, Deployment, Service (ClusterIP).
   - Практика:
     - самостоятельно пересоздать Deployment и Service с нуля для другого простого образа;
     - поэкспериментировать с количеством реплик и наблюдать изменения через kubectl get pods.
   - Цель: чтобы базовая механика (под → сервис → kubectl port-forward) выполнялась «на автомате».

2. ПРОБЫ ЗДОРОВЬЯ (LIVENESS / READINESS)
   - Теория: различия между livenessProbe и readinessProbe, зачем они нужны.
   - Практика:
     - добавить в FastAPI endpoint `/health`;
     - прописать HTTP-пробы в deployment.yaml;
     - смоделировать падение readiness (например, возвращать 500) и посмотреть поведение k8s.
   - Цель: понять, как Kubernetes решает, когда pod готов к трафику и когда его перезапускать.

3. РЕСУРСЫ И ЛИМИТЫ
   - Теория: requests и limits для CPU/памяти, влияние на scheduler и стабильность кластера.
   - Практика:
     - добавить в deployment.yaml resources.requests/limits;
     - сыграть с слишком маленькими/слишком большими значениями и посмотреть на ошибки и планирование.
   - Цель: сформировать интуицию, как задавать ресурсы под реальные сервисы.

4. АВТОСКЕЙЛИНГ (HPA)
   - Теория: Horizontal Pod Autoscaler, типичные метрики (CPU, custom metrics).
   - Практика:
     - включить metrics-server (если требуется);
     - создать HPA для web-deployment (минимум 2, максимум 5 реплик, target CPU, например, 60%);
     - сгенерировать нагрузку (ab/hey/locust) и посмотреть, как меняется количество pod’ов.
   - Цель: увидеть живой фидбек-loop «нагрузка → скейл → снижение нагрузки → дескейл».

5. ХРАНЕНИЕ ДАННЫХ (PVC + STATEFUL)
   - Теория: различие между Deployment и StatefulSet, PersistentVolume и PersistentVolumeClaim.
   - Практика:
     - добавить PVC и примонтировать его в FastAPI-поды для хранения файлов/логов;
     - убедиться, что данные сохраняются при перезапуске pod’ов и rolling updates.
   - Цель: понять работу со stateful-нагрузкой в k8s.

6. КОНФИГУРАЦИЯ И СЕКРЕТЫ (CONFIGMAP / SECRET)
   - Теория: ConfigMap для конфигов, Secret для чувствительных данных.
   - Практика:
     - вынести часть настроек (например, текст сообщения или флаг режима) в ConfigMap;
     - добавить секрет (фейковый API ключ) и использовать его как переменную окружения в контейнере.
   - Цель: научиться разделять код и конфигурацию.

7. БОЛЕЕ СЛОЖНЫЙ INGRESS
   - Теория: path-based и host-based routing, несколько сервисов за одним ingress.
   - Практика:
     - добавить второй сервис в кластер (например, /info);
     - настроить Ingress на маршрутизацию `/api` → web-service, `/info` → другой сервис.
   - Цель: почувствовать Ingress как простой, но мощный «роутер» HTTP-трафика.

8. CI/CD (БАЗОВЫЙ)
   - Теория: pipeline от git push до обновлённого деплоя в кластере.
   - Практика:
     - создать GitHub Actions workflow:
       - сборка Docker-образа;
       - пуш в registry;
       - автоматическое обновление Deployment через kubectl apply или kubectl set image.
   - Цель: увидеть, как код из репозитория автоматически попадает в кластер.

Для нового LLM важные входные артефакты:
- структура репозитория (описана в README),
- YAML-файлы (deployment.yaml, service.yaml, ingress.yaml),
- Dockerfile и main.py,
- текущий уровень пользователя: уверенно читает YAML, понимает Deployment/Service/Ingress, умеет собирать и запускать образ, готов углубляться в HPA, PVC и пробы.
