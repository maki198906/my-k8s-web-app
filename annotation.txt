# Аннотация проекта: URL Shortener на Kubernetes

## Описание
Полный учебный цикл: Python FastAPI сервис → Docker → Kubernetes (Docker Desktop, macOS).
Проект строился пошагово — от локального запуска до многокомпонентного K8s-деплоя с
автоскейлингом, персистентным хранилищем и отдельным фронтендом.

## Автор
Уверенный Python/ML-разработчик, осваивает DevOps и Kubernetes.

---

## Этапы и что изучено

### Этап 1 — FastAPI приложение
- Структура FastAPI: router, dependencies, Pydantic schemas, SQLAlchemy
- CRUD для SQLite: create_link, get_link_by_code, increment_hits, delete_link
- **Урок:** порядок регистрации маршрутов в FastAPI критичен.
  `/{code}` должен быть ПОСЛЕДНИМ — иначе "съедает" `/links`, `/health` и т.д.

### Этап 2 — Docker + Kubernetes базовый деплой
- Dockerfile: многослойная сборка, requirements.txt отдельным слоем от кода
- **Урок:** `docker build --no-cache` — когда Docker кешировал старый слой с неполным кодом
- PVC (PersistentVolumeClaim): SQLite на томе, данные переживают рестарт подов
- ConfigMap: несекретные настройки (BASE_URL, APP_NAME) в переменных окружения
- Secret: создавать через `kubectl create secret generic --from-env-file=.env`,
  НЕ хранить значения в secret.yaml (коммитить в git только структуру)
- Readiness/Liveness Probes: K8s не шлёт трафик пока readinessProbe не прошла
- Resources requests/limits: CPU в миллиядрах (100m = 0.1 core), память в Mi
- **Урок:** при изменении ConfigMap/Secret поды НЕ рестартуют автоматически.
  Нужен `kubectl rollout restart deployment/<name>`
- **Урок:** ошибка "field is immutable" при apply — нужно удалить старый Deployment
  если изменился spec.selector

### Этап 3 — HPA (Horizontal Pod Autoscaler)
- metrics-server: обязателен для HPA, в Docker Desktop требует --kubelet-insecure-tls
- HPA Controller опрашивает metrics-server каждые 15с, регулирует replicas
- 500/502 под нагрузкой при скейлинге — нормально, окно между "под создан"
  и "readinessProbe прошла". Лечится агрессивнее настроенными пробами
- cooldown period ~5 минут — защита от флаппинга при скейлинге вниз
- **Урок:** для учебного стенда targetCPUUtilization: 30% лучше чем 60%
  (сервис лёгкий, иначе скейлинг почти не срабатывает)

### Этап 4 — Frontend + Path-based Ingress
- APIRouter с префиксом /api: чистое разделение маршрутов
- Отдельный nginx pod для статики — правильная архитектура (разделение ответственности)
- **Урок:** порядок paths в Ingress: /api и /r ВЫШЕ /, иначе все запросы уйдут в nginx
- **Урок:** port-forward — инструмент разработчика, не продакшн. В продакшне
  маршрутизация только через Ingress, не через proxy_pass в подах
- **Урок:** probe path обновляется вместе с кодом! После переноса /health → /api/health
  нужно обновить deployment.yaml, иначе CrashLoopBackOff

## Диагностические команды (шпаргалка)

```bash
kubectl get pods,svc,ingress,hpa,pvc    # общее состояние
kubectl describe pod <name>              # детали + события пода
kubectl logs <pod> --previous            # логи упавшего пода
kubectl get endpoints                    # видит ли Service поды?
kubectl top pods                         # CPU/RAM (нужен metrics-server)
kubectl rollout restart deployment/<n>   # рестарт без даунтайма
kubectl rollout status deployment/<n>    # прогресс rolling update
```

## Типичные ошибки и решения

| Симптом | Причина | Решение |
|---------|---------|---------|
| ImagePullBackOff | Образ не найден в registry | imagePullPolicy: Never для локальных образов |
| CrashLoopBackOff | Probe путь не совпадает с кодом | Обновить path в deployment.yaml |
| Endpoints пустой | selector в Service ≠ labels на подах | Проверить labels, rollout restart |
| 404 на /links | Порядок маршрутов в FastAPI | Конкретные пути выше /{code} |
| 502 Bad Gateway | Под не прошёл readinessProbe | kubectl logs --previous, исправить probe |
| Secret не обновился | Поды не рестартовали | kubectl rollout restart |
| "field is immutable" | Изменился spec.selector | kubectl delete + apply deployment |
